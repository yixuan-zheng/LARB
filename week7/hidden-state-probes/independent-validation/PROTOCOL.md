# Independent AIME validation v1

## Cohort and estimand

The primary question is whether the frozen 4K hidden-state probe allocates extra reasoning more effectively than the frozen prompt-only probe on questions held out from LARB development. The population is text-only historical AIME questions and trajectories still thinking at 4,096 tokens. Public AIME may have appeared in Qwen training. This validates transfer to different LARB questions under the same generator and decoding policy.

Use the 180 IDs in `cohort-v1.json`, ten per contest form per year from 2015 through 2023, selected by SHA-256 order. The pinned [source revision](https://huggingface.co/datasets/di-zhang-fdu/AIME_1983_2024/tree/3e2cc86390666c5c756622afc0eeb9e6194496bc) supplied 269 rows in those years. Of these, 247 passed the text-only, integer-key and overlap screen. Exclusions were 20 embedded diagrams, one invalid key, and one normalized text or near-text match to the workspace inventory. The audit covered 1,718 distinct prior strings in materialized JSON, JSONL and CSV across Weeks 1–7, including the Week 6 and Week 7 AIME inputs in their materialized JSON form and the other archived question sets available as text. The known 2024–2026 AIME editions are outside the candidate years. The screen catches normalized containment and high trigram overlap. This inventory cannot establish absence from undocumented runs, archive-only sources or arbitrarily rephrased copies. Before staging, verify the original source bytes, selected question hashes and grader keys against the manifest and source. Stop for review on a source or cohort discrepancy.

Generate two planned prefixes per question, using independent, stable request-local seeds. Before inference, enumerate all prefix and suffix identities by cohort version, question ID, seed slot, arm and draw index. Use the Experiment 2 SHA-256 seed scheme with a new namespace, deterministic collision resolution, and a reserved set of prior recorded seeds. Freeze the seed ledger and verify that it regenerates identically. A naturally closed trajectory before the checkpoint is logged as ineligible. Do not replace it, change its seed or select another question. An interrupted call is retried with the identical seed and verified input hash. Require exactly 4,096 reasoning tokens and no prior thinking closure for each eligible trajectory. Use exact prompt and reasoning token IDs throughout. Record all 360 prefix attempts, eligibility by question and both seed slots. All policy comparisons are conditional on eligible checkpoints.

## Frozen probe and sealed forecasts

Use Qwen/Qwen3-4B BF16 at revision `1cfa9a7208912126459214e8b04321603b3df60c`. Replay the exact input IDs using the [Temporal Predictors](https://arxiv.org/abs/2511.14773) per-checkpoint forward path from the archived direct-reference run. Extract the final-layer mean of the last four positions at 4K and the existing prompt-only final-layer last token at checkpoint zero. Use the upstream snapshot and runtime pinned in the direct-reference configuration. Skip unused temporal checkpoints.

Fit the two representations separately on the same 58 Week 7 development checkpoints and all eight development draws per arm. This is the final transfer fit using all available training labels, with the same learning rule as the exploratory fits. Each representation has a training-only PCA with up to 128 components capped by training rank, and separate L2 logistic heads for p4 and p8 using the binary success/failure frequency weights. Use scikit-learn 1.7.2, liblinear, C=1, max_iter=1000, random_state=356, and no class balancing or calibration. The final PCA has 57 components per representation. `probes-v1.npz` freezes the fitted numeric arrays. Validate its checksum before inference. Rank by predicted p8 minus predicted p4.

Generate all checkpoint and prompt-only scores and seal the full forecast table, feature manifest, input hashes and allocated weights before opening the grading join. The 12 engineering gate draws may be committed earlier under a separate path with no answer key and no grading or outcome access for the forecasting process. Other suffixes run after sealing. Neither model training nor forecast generation may read validation answers, suffixes, grades, cap flags, or output lengths. Keep all release, run and grader paths separate from the existing experiments.

## Outcome collection and evaluation

Use eight independent short answers and eight independent long continuations per eligible prefix. Reuse the Experiment 2 vLLM 0.11.2, Torch 2.9.0 and Transformers 4.57.6 stack, temperature 0.6, top-p 0.95, top-k 20, forced cue and 2,048-token answer allowance. Re-prefill the saved input IDs for every suffix. Use one active sequence and disabled prefix caching. The short arm forces the transition at 4,096. The long arm honors natural closure or forces the transition at 8,192. Grade only the final-phase boxed integer with the existing grader and a separate verified answer-key file. Incorrect, capped, malformed and invalid completed responses score zero with reason codes. Infrastructure failures remain missing. Resume only uncommitted calls with the original seed and preserve interruption evidence. Withhold the primary decision for missing draws and report worst-case lift bounds if the run cannot be completed.

For M eligible checkpoints, extend exactly floor(M/2) for both probes, preserving fractional uniform weights at tied cutoffs. For each policy report sum(p4 + weight × (p8 − p4)) using the eight held-out draws per arm as empirical rates. Report expected correct answers, paired lift and lift in percentage points, beneficial and harmful selections, missed positive empirical contrasts, and summed gains and losses. These empirical signs have Monte Carlo error at eight draws. Include all-short and all-long references, plus arm calibration and a descriptive within-question comparison on the two-seed subset. Use 10,000 paired question-cluster bootstraps with seed 356 and percentile 95% intervals. Resample all attempted question groups with their eligible seeds, recompute floor(M/2) and both cutoffs in each replicate, and report lift per eligible prefix and expected-correct equivalent at the observed M. Intervals condition on fixed fitted probes and observed suffix draws. Report measured output suffix tokens, re-prefill tokens, call latency, allocation time and queue time separately. Use the same fractional weights on mean measured tokens and call time to estimate each policy's accuracy–cost pair.

Use the development practical threshold of 2/58 = 3.45 percentage points. Call validation positive when the observed lift reaches that threshold and its lower 95% bound exceeds zero. Call it below the practical threshold when its upper 95% bound is below 3.45 points. Otherwise call it inconclusive. Apply the positive rule first if classifying from rounded numbers, and compute all decisions from unrounded values. Keep the eight-draw estimate as the single primary analysis. No interim efficacy scoring, cohort selection, recalibration or model updates.

## Planning and resource gate

The prior 29-question development interval implies a rough per-question scale of 0.172 in eligible-prefix accuracy units. Use the average half-width of that interval divided by 1.96, then multiply by sqrt(29). Under a normal approximation, the lift detectable against zero with 80% power at two-sided 5% is 2.80 × 0.172 / sqrt(question count). This planning proxy assumes similar question clustering, policy variance and eligibility. The new fit, historical question mix and eight test draws may change variance. Power against zero differs from the chance of satisfying the practical point-estimate rule. Near a true lift of 3.66 points, that point-estimate rule alone would pass only about 57% of the time at 180 questions. A two-sided interval with lower bound above 3.45 points would require substantially more data to establish the magnitude precisely.

Cost assumes two eligible checkpoints per question, 58.64 seconds per prefix averaged across the 60 archived Week 7 prefix calls, and 22.22 seconds per short draw and 77.19 per long draw from Experiment 2. At 180 questions the ceiling is 360 prefixes and 5,760 draws, roughly 18.6M generated suffix tokens at the Experiment 2 mean. The 85.4-hour base estimate covers generation and repeated prefills. Budget 95–105 allocated L40S hours including engineering, feature replay, startup, clean resume margins and variation, excluding queue time. The previous full direct-reference extraction of 115 trajectories took 5m22 and reserved 9.48 GiB, so the two-checkpoint extraction should be a small portion of the budget. Verify by measuring it.

Request one L40S, 8 CPUs and 64 GiB host memory for a one-hour gate. Use the preplanned seed slots on the first three distinct questions by independent gate hash, following that hash order if eligibility requires moving to another question. Exercise one eligible checkpoint per question and the first two draws per arm, 12 suffix calls, expected to take about ten minutes excluding setup. Verify identical prompt and checkpoint token hashes, opening and natural or forced closure handling, isolated seeds and requests, final-answer phase behavior, atomic resume and complete records. Check feature shape, nonzero finite values, direct-reference parity at relative L2 ≤ 0.02 and cosine ≥ 0.999, peak extraction memory ≤ 36 GiB and positive sampled free serving memory. Use the existing 300-second call deadline and 1,200-second suffix gate deadline. Require at least one normally terminated answer per arm without inspecting its correctness. Preserve gate outputs and stop on any failed check. Count valid committed gate draws in the full schedule if execution proceeds. Treat the runtime projection as provisional from 12 calls and stop for review if it projects beyond the 105-hour cap.

Stage remaining prefix collection, feature extraction and forecast sealing, then the serial suffix run. Keep one writer and reuse the Experiment 2 three-hour allocation and safe-stop mechanism. Allow roughly 32–35 three-hour allocation equivalents including all stages. Verify the actual first full allocation's throughput before reserving more. Pause and preserve data if the reviewed GPU-hour cap is approached, with no outcome-dependent early stopping or silent reduction of the cohort. A smaller budget can support a separately frozen feasibility study, with the precision in the table.

This release freezes the cohort, predictor and evaluation protocol for review. GPU staging still needs a dedicated prefix-only adapter and CPU integration checks for the sealed-forecast join, seed ledger and resumable schedule before the gate. No PACE allocation has been submitted.
