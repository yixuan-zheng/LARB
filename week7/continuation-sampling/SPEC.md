# Experiment 2 | Repeated continuation sampling

## Target

For each of the 58 eligible Week 7 checkpoints, estimate the probability of a normally completed correct final answer under two policies: stop thinking at 4,096 tokens, or allow thinking until natural closure or 8,192 tokens. Denote these by p4 and p8. The marginal correctness benefit is p8 − p4. Eight new independently seeded suffixes per arm, 928 calls total, are the initial design. Repeated short draws are needed because a trajectory with high p8 can already have high p4. Each observed success changes a per-arm estimate by 12.5 percentage points at eight draws, so individual rankings will remain noisy.

For two independent draws, the probability that only the longer policy answers correctly is (1−p4)p8, and the probability that only the shorter policy answers correctly is p4(1−p8). Their difference equals p8−p4. These are joint probabilities under the stated independent-draw convention. A trajectory's true p8−p4 is a fixed conditional contrast. The experiment cannot identify an individual counterfactual transition under an unspecified coupling of the sampling randomness.

Math-Shepherd estimates step quality by grading repeated completions from an intermediate step, including a soft score based on the correct fraction. Experiment 2 borrows that estimator for a fixed checkpoint and adds the matched shorter-budget arm. It uses the original generator and existing final-answer grader. It does not train a process reward model, rerank candidate answers, or perform reinforcement learning. [Math-Shepherd, §3.3](https://arxiv.org/html/2312.08935)

## Sampling and grading

Use the exact saved prompt IDs and 4,096 prefix IDs from PACE job 6958397. Verify the raw checkpoint call against the pair artifact and preserve the token hash. Each request receives a fresh prefix copy, engine request ID and RNG seed. SHA-256 derives a stable seed from the call identity, with collision resolution against all planned and earlier executed seeds. The pilot shares the same identities for overlapping planned draws. Original Week 7 suffixes inform resource estimates and are excluded from the new point estimates.

Keep the original Qwen3-4B BF16 revision, vLLM 0.11.2, Torch 2.9.0, Transformers 4.57.6, temperature 0.6, top-p 0.95, top-k 20, forced cue and 2,048-token legacy answer allowance. Respect natural thinking closure. Reuse the executed request-local worker and control logic. One active sequence and disabled prefix caching match the original execution. Each independent request re-prefills the same original token IDs.

Use the existing final-phase boxed-integer grader locally with the verified original answer-key file. Wrong, capped, malformed and invalid completed responses score zero with reason codes. Infrastructure interruptions leave the call missing. Report missing-data bounds and withhold point estimates for incomplete arms. After an explicit resume, only uncommitted identities run again with their frozen seeds, and earlier attempt records remain. Keep one writer per output directory. Completed records use atomic rename and are validated before skipping. A resume checks the identical manifest, including release, model path, and GPU type, visible memory and driver. Report per-call input and suffix token counts, first-output time as a prefill-inclusive proxy, total latency and sampled free device memory. GPU kernel-level peak memory remains unmeasured.

Report per-prefix p4, p8 and delta, Wilson intervals for arm probabilities, and an approximate conservative delta interval from Bonferroni-adjusted Wilson limits. Report a question-cluster bootstrap for the mean prefix contrast with both seeds kept together. The bootstrap resamples observed question groups and conditions on the measured per-prefix draws. The interval is not a substitute for per-prefix Monte Carlo uncertainty. Report missing-data bounds for the cohort even if some arms are incomplete. Use the pilot only to verify mechanics and size the full study.

## Pilot and scale

Pilot selection is deterministic and outcome-independent by hash, with three distinct questions and one saved prefix per question. Run two draws per arm per prefix, 12 requests, as the first committed samples of the full schedule on one L40S with 8 CPUs and 64 GB host memory. The integrated gate checks the 12 planned identities, prefix and suffix hashes, cue and answer phase, at least one normal answer per arm, startup and per-call time bounds, and positive sampled free device memory. If it fails, preserve artifacts and exit before additional draws. If it passes, proceed in the same engine and retain all 12 gate draws in the full estimates. Check cue and EOS behavior, input hashes, GPU memory, runtime and record completeness. Confirm that both arms can generate final answers. Record natural and forced closures where observed, without requiring a particular correctness count. CPU fixtures cover the forced boundaries and natural closure explicitly.

The prior L40S run averaged 21.7 seconds per short suffix and 75.6 per long suffix, including their repeated prefills. Those means imply roughly 9.7 minutes for the 12 pilot suffixes and 12.5 GPU-hours for all 928 suffixes before startup and margins. Full-run volume is approximately 2.95M suffix output tokens and at least 3.80M re-prefilled reasoning tokens, plus prompts. Use pilot timings to size future jobs. A planning range is 14–17 GPU-hours with overhead and variation. Use three-hour allocations with one writer and explicit serial resume of the same frozen schedule. The runner checks its elapsed time before each call, reserves at least 330 seconds before its internal deadline and checkpoints cleanly. The internal deadline is 174 minutes and the outer timeout is 178 minutes. Future allocations reuse the same run directory and skip every committed draw. Expect roughly five to seven allocations pending observed throughput. Parallel sharding is outside this execution plan.

## Isolation and later predictor evaluation

The Experiment 2 release contains saved input IDs, code, settings and source hashes. Answer keys and branch outcomes stay out of that release and out of Experiment 1 inputs. Experiment 2 writes its own manifests and outputs. The two experiments can run concurrently, subject to Slurm capacity and account limits. Neither code path uses the other's results.

The Monte Carlo estimates are retrospective reference labels. An online predictor can later be frozen using only question and pre-checkpoint inputs, then sealed before the grading join. Compare predicted p4, p8 and delta against these measured targets, with matched-allocation accuracy and question-cluster uncertainty. Use question-disjoint data for generalization and retain an evaluation-only grading join. Repeated draws reduce label noise for a fixed generator and decoding policy. They do not establish generalization to new questions, other generators or serving goodput.

This specification authorizes only the serial execution design. Allocation records and submitted job IDs are tracked in README.md.
